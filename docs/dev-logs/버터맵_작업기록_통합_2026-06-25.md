## 🔄 4방향 턴테이블 (★결정적)
![[고목비교/compare_grid_4각도.png]]

> 단일 각도론 판단 오류 가능 → 4방향으로 봐야 진실이 보임.

## 📊 평가 (턴테이블 기준 — 정정됨)

| 항목 | Meshy | Rodin |
|---|---|---|
| **입체감** | ❌ **납작(2.5D relief)** — 4각도 거의 동일 | ✅ **완전한 3D** — 사방 다름 |
| 나선 가지 | 평면에 눌림 | ✅ 공간에 입체로 (90°에서 뚜렷) |
| 뿌리/밑동 | 양호 | ✅ 더 디테일 |
| 텍스처 | 부드러움/어두움 | ✅ 더 선명한 bark |
| 폴리수 | 31k | 34k (둘 다 Nanite OK) |

## 🎯 결론 (정정)
- **Rodin 명확한 승자** — 진짜 3D 볼륨, walk-around 가능.
- **Meshy는 납작** — 정면 한 컷만 OK. **원경/빌보드** 용도면 싸게 쓸 수 있음.
- ⚠️ 교훈: **단일 각도 비교는 위험** (Meshy가 정면만 그럴듯). 항상 **턴테이블로 검증**.
- **고목 같은 오가닉도 Rodin 추천** (당초 "오가닉=Meshy" 가정 폐기).

## 🔬 Rodin Regular vs Detail+HighPack
![[고목비교/compare_Regular_vs_Detail.png]]

| | Regular | Detail+HighPack |
|---|---|---|
| 폴리 | 34k | **90k** (2.7배) |
| FBX/텍스처 | 8MB / 2K | 32MB / **4K** |
| bark·가지·뿌리 | 양호 | ✅ 결 선명·날카로움·우락부락 |

**기준**: 전경 히어로(가까이) = **Detail** / 중경·배경 = **Regular** / 원경 = Meshy 납작.
→ 전부 Detail은 낭비. "가까이 보이는 것만 Detail".

## 🧪 Meshy 멀티이미지 테스트 (정면+AI측면)
![[고목비교/compare_Meshy_single_vs_multi.png]]

- AI(Seedream)로 만든 측면뷰 추가해 Meshy 멀티이미지 → **여전히 납작** (단일과 거의 동일, 31k tris)
- 원인: AI 측면뷰가 정면과 **기하학적 불일치** → Meshy가 깊이 못 만듦
- **결론**: AI 컨셉 1장 기반 파이프라인에선 멀티이미지 효과 없음 → **Rodin 확정**
- (진짜 일관된 턴테이블 사진이 있으면 Meshy 멀티도 유효하나, 우리 워크플로우엔 해당 없음)

## 1. 레퍼런스 수집 (00:26)

![[북유럽환경_frames/06_레퍼런스수집_15-05.jpg]]

- 회사에서는 보통 **컨셉 원화 + 레벨 디자인**이 먼저 나온 뒤 배경 제작 시작
- 컨셉 원화가 없으면 **MidJourney**(미드저니)로 분위기용 이미지 + 사진/게임 레퍼런스 수집
- ⭐ **게임 레퍼런스는 "보는 것"이 아니라 "어떻게 만들었는지 분석"** 하는 게 핵심:
  - 랜드스케이프에 어떤 에셋을 썼나 / 원경 처리 방식 / 타일 텍스처 종류 수 / 식생 밀도·종류
- 리소스를 많이 넣으면 비주얼은 풍성해지지만, **한정된 리소스로 얼마나 효율적으로 분위기를 내느냐**가 더 중요

## 2. 프로젝트 세팅 (01:22)

![[북유럽환경_frames/01_프로젝트생성_0-00.jpg]]

- **UE 5.5.4** / 프로젝트 브라우저 게임 탭 → **Third Person 템플릿**
  - 캐릭터를 직접 움직이며 **플레이어 시점**으로 배경 확인 가능
- 생성 후 **Map / Material / Mesh 폴더** 분리, 새 레벨 생성
- 오픈월드 템플릿 레벨은 **World Partition** 기반이라 이번엔 미사용 → **빈 레벨**로 진행
- 기본 라이팅 세팅 후, 이 맵에서 머티리얼·에셋 조합·분위기를 **미리 테스트**

## 3. 랜드스케이프 머티리얼 (02:22)

![[북유럽환경_frames/02_랜드스케이프머티리얼_5-00.jpg]]

- 랜드스케이프 머티리얼 = 흙·바위·풀·모래 등 **여러 레이어를 섞어 지형에 직접 페인팅**
- **레이어 1개 구성**: Base Color + Normal + Mask Texture
  - Mask Texture 안에 **AO / Roughness / Height** 정보 포함
- 색상 강도·노멀 강도·Roughness 등 나중에 조절할 값은 전부 **파라미터화** (네이밍 정리 필수)
- ⭐ **레이어 구성을 Material Function으로 정리** → 다른 레이어에서 같은 구조 재사용 (관리 ↑)
- 구조 복사 → 여러 Landscape 레이어 → **Landscape Layer Blend** 노드에 연결
- Paint 탭에서 레이어 인포 생성 후 브러시로 칠해 동작 확인
- 이번 예제는 **총 4개 레이어**, Blend 타입은 **Height Blend** (높이 정보 기준 블렌딩 → 경계가 자연스러움)

## 4. 바닥 텍스처 적용 (04:41)

- 텍스처는 **Quixel Bridge**에서 가져옴 (Grass부터 적용)
- ⭐ **Post Process Volume 추가 → 노출(Exposure) 최소/최대값을 같게 고정**
  - 화면 밝기가 자동으로 안 바뀌어서 **텍스처 톤을 안정적으로 판단** 가능
- 풀 → 흙 → 자갈 순으로 레이어 텍스처 배치, 톤이 안 맞으면 **Material Instance**에서 밝기·색상 조정
- 초기엔 정답을 찾기보다 **여러 텍스처를 계속 바꿔보며** 분위기 탐색
- 페인팅 후 **반드시 캐릭터 시점**에서 크기감·밀도감·반복 패턴 체크

> [!tip] 퀵셀 브릿지 마스터 머티리얼
> UE는 범용 환경 머티리얼을 기본 제공하지 않음. **Quixel Bridge 설치 시 MS 프리셋의 마스터 머티리얼** 사용 가능 — 머티리얼 제작이 익숙치 않으면 그대로 써도 됨. (영상 제작자는 기능 추가/수정 편의를 위해 직접 제작)

## 5. 폴리지·기본 머티리얼 (06:40)

![[북유럽환경_frames/03_머티리얼함수_7-20.jpg]]

- **폴리지 머티리얼**: 랜드스케이프 레이어 함수를 수정해 빠르게 제작
  - 타일링 불필요 → 제거 / Mask에 **Alpha·Roughness·Translucency Mask**
  - **Subsurface Color** 텍스처 추가 (식생 반투명 표현 / SSS)
  - Blend Mode·Shading Model을 폴리지용으로, **Wind(Simple Grass Wind)** 함수로 추가
- **기본 오브젝트 머티리얼**: Mask에 AO·Roughness·Metallic / Metallic 파라미터 추가
  - 폴리지의 Translucency 관련 제거, Wind 제거
- ⭐ **함수 구조로 만들면 기능을 조립하듯 추가/제거** 가능 → 관리 편함
- Blend Mode는 **Masked로 통일** (나중에 거리 페이드·디더링 추가 대비)

## 6. 랜드스케이프 그레스 타입 (08:48)

![[북유럽환경_frames/04_폴리지그레스_9-55.jpg]]

- **PCG vs 랜드스케이프 그레스 타입**:
  - PCG = 규칙 기반 대규모 자동 배치 → **오픈월드/넓은 필드**에 유리
  - 그레스 타입 = 설정 간단·빠른 확인 → **잔디·작은 식생**에 여전히 많이 씀 (정답 없음, 프로젝트 성향에 맞게)
- Landscape Layer Sample → Grass Output 연결 → 그레스 타입 에셋 설정
- 적용 안 되면 **레이어를 한번 칠해주면 갱신**됨
- ⚠️ 그레스 타입은 **콜리전 미지원** → 풀·작은 나뭇가지·돌멩이 등 **플레이에 영향 없는 에셋**에만
- 여러 식물을 **하나의 스태틱 메쉬 덩어리로 병합** → 적은 오브젝트 수로 넓은 영역 채움 (관리·성능 ↑)
- ⭐ 텍스처 선택 시 **나중에 배치될 지면 에셋도 함께 고려**: 흙→마른 풀/작은 돌, 풀밭→잡초/꽃

## 7. 물웅덩이(퍼들) 표현 (11:46)

![[북유럽환경_frames/05_레이어페인팅_12-30.jpg]]

- 레퍼런스에 물 흐르는 구간 있어서 군데군데 **물웅덩이를 펑션으로 표현**
  - 랜드스케이프 텍스처의 **Height 정보 기반** → 높이에 따라 웅덩이 생성
  - 물 깊이·색상·가장자리·범위를 파라미터화
- ⚠️ 물 영역에 그레스가 자라는 어색함 방지 → **Remove Foliage 레이어** 추가
  - 퍼들 마스크 값을 가져와 그레스 타입이 안 생기도록 연결

## 8. 에셋 선별·배치 — 테스트 레벨 (13:04)

![[북유럽환경_frames/07_에셋배치_17-40.jpg]]

- 브릿지에서 에셋 선별 후 **테스트 레벨에서 현재 지형과 어울리는지 확인**
- 색감·스케일·노멀 강도·Roughness 조정하며 하나씩 세팅
- ⭐ **반드시 실제 플레이 시점**에서 확인 — 에셋만 보면 괜찮아도 배치하면 크기·색감 어색한 경우 多
- **대형 에셋** = 지형 실루엣에 큰 영향 → 여러 방향 돌려가며 배치
- **바닥 에셋** = 대형 에셋과 랜드스케이프 경계를 자연스럽게 연결 + 타일링 완화 + 시선 머무는 곳 디테일
- 식물도 **여러 개를 하나의 덩어리 메쉬**로 → 저(低)오브젝트로 넓은 영역 (성능 유리)
- 테스트 레벨 = 에셋 모아두는 곳이 아니라 **방향성·분위기 검증 과정**

## 9~10. 본 씬 구성 & 배치 반복 (15:36 / 16:44)

![[북유럽환경_frames/08_물과라이팅_20-15.jpg]]

- 월드 크리에이터/가이아 같은 툴도 있지만 이번엔 **소규모라 직접 지형 제작**
- 좌우에 **큰 둔덕** 배치 → 전체 지형 실루엣 잡기
- 흐르는 물 = **Water Body River** (랜드스케이프 연동, 스플라인으로 폭·깊이·색 조절)
- 물길 주변 **자갈 레이어 + 퍼들 레이어** 페인팅 → 물과 지면 자연스럽게 연결

> [!quote] 핵심 마인드셋 (16:44~)
> 초반엔 마음에 안 들어 자꾸 처음부터 다시 만들고 싶어짐 → 하지만 그러면 끝까지 못 감 (**"문제집 첫 단원만 너덜너덜"**).
> 자연환경은 정답이 정해진 분야가 아님. **큰 형태 먼저 잡고 → 반복 수정으로 완성도 ↑** 가 훨씬 효율적.

- 같은 에셋도 **회전·크기 변경**으로 반복성 줄이기
- ⭐ 구역마다 **조금씩 차이**를 줘야 함 → 사방이 비슷하면 플레이어가 **현재 위치 인지 어려움**

## 11. 하늘·안개 (19:12)

- 빠르게 분위기 잡기 위해 **HDRI Backdrop** 사용 (360° 환경 이미지)
  - HDRI의 조명 정보를 Sky Light가 받아 → 적은 설정으로 자연스러운 환경감·반사
- **Exponential Height Fog** 함께 조정 (밀도·높이·색상)
  - 원경 오브젝트의 대비를 줄여 **거리감·공간감** 표현
- ※ 최종 결과물은 별도 하늘 시스템/라이팅을 쓰는 경우도 많지만, 여기선 빠른 분위기 잡기용

## 12. 폴리지 배치 (20:49)

- 폴리지 모드에서 식생 에셋 등록 → 원하는 영역에 배치
- ⭐ **무작정 채우지 말고 배치 규칙 먼저 정하기** (기준 없으면 구역마다 달라져 통일감 ↓)
- 에셋과 랜드스케이프가 **맞닿는 경계엔 폴리지 배치** → 단절감 제거
- 바위/구조물이 지면에 그냥 놓이면 인위적 → **주변에 식생 추가로 경계 부드럽게**
  - 예: 지형이 꺾이는 곳엔 덩굴성 식물, 바위-지면 경계엔 작은 풀로 위화감 가리기
- 작은 디테일 에셋(물·풀·낙엽)이 쌓이면 **장면 밀도·현실감·완성도** ↑ (특히 근접 영역)

## 14. 후반 효과 — 흐르는 구름 그림자 (24:08)

![[북유럽환경_frames/10_최종시네마틱_25-24.jpg]]

- 하늘 구름 그림자가 천천히 지나가는 효과로 화면에 **움직임** 부여
- 방법: 타일링 구름 텍스처 → **Light Function 머티리얼** 제작
  - Material Domain = **Light Function** → **Directional Light**의 Light Function 슬롯에 연결
  - **UV를 시간에 따라 천천히 이동** → 구름 그림자가 흐르는 느낌 (속도·강도 파라미터화)
- 마지막으로 Directional Light Intensity + Light Function 밝기를 함께 조정 (과하지 않게)
- ※ 이후 **최적화** 과정이 남지만 플랫폼별 기준이 달라 영상에서는 미다룸

## 💡 핵심 노하우 정리 (면접·실무용)

1. **레퍼런스는 분석하며 본다** — 에셋 종류/원경/타일 수/식생 밀도까지 역설계
2. **효율 > 물량** — 한정 리소스로 분위기 내기 (덩어리 메쉬 병합, 함수 재사용)
3. **Material Function 재사용 구조** — 레이어/폴리지/기본 머티리얼을 함수로 조립
4. **Post Process로 노출 고정** — 텍스처 톤을 일관되게 판단
5. **항상 캐릭터/플레이 시점에서 검증** — 에셋 단독 ≠ 레벨 배치 결과
6. **큰 형태 먼저 → 반복 수정** — 처음부터 완벽 추구 X ("첫 단원만 너덜너덜" 경계)
7. **구역별 차별화** — 길찾기·위치 인지를 위해 사방을 다르게
8. **경계 처리** — 에셋-지형 맞닿는 곳에 폴리지로 단절감 제거
9. **콜리전 주의** — 그레스 타입은 콜리전 미지원, 플레이 영향 없는 곳만

## 한 줄 설정

> **죽음이 없던 평화로운 세계. 그러나 자신의 죽음을 두려워한 세계수가, 죽음 그 자체인 존재 '니펠'을 삼켜버린다. 생명의 근원에 죽음이 깃들자 세계수는 타락했고, 그 죽음은 세상 전체로 역류했다. 주인공 버터는 모든 비극의 근원이 된 세계수를 죽이러 간다.**

---

## 이 세계는 어떤 곳인가 (원작을 몰라도 됨)

- **엘리아스**: 거대한 나무 **'세계수'**가 다스리는 판타지 세계. 항상 봄이고 평화롭다.
- **죽음이 없는 세계 (원작 설정)**: 원래 이 세계의 생명체는 **죽지 않는다.** 치명상을 입어도 씨앗으로 변해 묻혔다 부활한다. 이 부활을 **'주말 농장'**이라 부른다. → 세계수가 **죽음을 두려워해 죽음을 지웠기** 때문 (원작 설정).
- **니펠 (죽음의 화신)**: 원래 세계에 들어온 '죽음'이라는 관념으로부터, **세계수의 힘으로 태어난 최초의 유령.** 죽음·저승(주말농장)을 관장하는 존재. 세계수는 두려운 나머지 니펠을 **봉인**해 두었다 (원작: "세계수의 실수로 태어난 금단의 존재").

> [!tip] 이 게임의 IF (만약에…)
> 트릭컬엔 여러 평행세계(멀티버스)가 있다 (원작 공식 설정).
> 이 게임은 그중 **"세계수가 죽음을 삼키는 선택을 해버린, 단 하나의 독립된 차원"**을 무대로 한다.
> 다른 세계와 합쳐지거나 넘나들지 않는다. **이 세계 하나로 완결되는 별개의 이야기**다.

---

## 핵심 사건: "세계수가 죽음을 삼키다" (타락의 원인)

이 세계관 **모든 비극의 시작점.**

1. **세계수의 쇠락** — 세계수는 수명이 다해 **썩어가기 시작한다** (원작 설정). 즉, **자신의 죽음**이 다가온다.
2. **공포와 모순된 선택** — 죽음을 누구보다 두려워하던 세계수는, 죽음을 *지배하면 죽지 않으리라* 여기고 **봉인했던 니펠(죽음 그 자체)을 삼켜버린다.**
3. **죽음의 재탑재** — 죽음을 삼킨 세계수는 이제 **죽음을 품은 생명의 나무**가 된다. 생명의 근원에 죽음이 깃든 근본적 모순.
4. **타락 (부작용)** — 모순을 견디지 못한 세계수는 **뒤틀리고 부패한다.** 통제하려던 죽음이 오히려 세계수를 잠식한다.
5. **죽음의 역류** — 세계수는 만물의 뿌리이므로, 그 죽음이 **세계 전체로 흘러넘친다.** 주말 농장(부활)이 무너지고, **죽지 않던 존재들이 처음으로 죽기 시작한다.**

> [!warning] 왜 이 설정이 강력한가
> - **최고의 비극적 적**: 최종 적이 침략자가 아니라, **죽음이 두려워 발버둥 친 세계수 자신.** 동정과 증오가 뒤섞인다.
> - **너의 핵심 훅 그대로**: "죽음의 탄생"이 세계수의 선택에서 비롯 → 동력이 명확하다.
> - **시스템 정당화**: 플레이어 HP 0 = 진짜 죽음(게임오버)인 이유가 세계관에 박힘.
> - **정사 100% 활용**: 세계수 쇠락·죽음 공포·니펠·주말농장·금단의 봉인 전부 공식 설정을 *비틀어* 재해석 → 창작성 + 규약 안전 → [[notes/Project_New/2차창작_규약체크.md|규약 체크]]

## 니펠은 어디에? (흡수되어 소멸)

- 니펠은 세계수에게 **완전히 삼켜져 소멸**했다. **별도 인물/보스로 등장하지 않는다.**
- 니펠은 "죽음 그 자체"였으므로, 그를 삼킨 것이 곧 **세계수가 죽음을 떠안은 사건** = 타락의 직접 원인이다.
- 즉 니펠은 **세계관의 배경 장치**일 뿐, 화면에 나오는 캐릭터가 아니다. (이름조차 잊혔을 수 있음)

## 타락 시스템 — "감정의 개화(開花)"

> [!info] 보스들이 *어떻게* 괴물이 되는가에 대한 공통 법칙
> 모든 보스는 제각각이 아니라, **이 하나의 규칙**으로 타락한다. 그래서 세계관이 일관된다.

**한 줄**: 죽음이 역류하자, 죽음을 처음 겪는 존재들의 마음속 **부정적인 감정(공포·절망·분노·집착·상실)이 통제를 잃고 "피어나(개화)"**, 그 존재를 뒤틀린 괴물의 형태로 굳혀버린다.

### 타락 엔진 = "어사이드의 폭주" (감정의 개화)

> [!info] 어사이드(Aside)란? — 정사 설정
> 사도의 **욕망·소망·억눌린 추억이 실체화된 존재.** 원래는 당사자·(교주)·영춘에게만 보인다.
> → 이 세계는 본래부터 **"마음이 형체를 갖는"** 세계다. 타락은 이 장치를 비튼 것.

1. **죽음의 공포**가 마음을 두드린다 (죽음을 한 번도 몰랐기에 충격이 더 크다)
2. 부정 감정이 폭주 → 그 사람의 **어사이드가 흉포하게 자라 "개화"한다** — 검은 꽃·가시·넝쿨처럼 몸에서 솟음 *(트릭컬 = 식물이 지성을 가진 세계 → 정사 톤과 직결)*
3. 폭주한 어사이드가 본체와 얽혀 **타락한 괴물(보스)**이 된다
4. 세계의 규칙이 무너져, 어사이드는 이제 **누구의 눈에나 보일 만큼 완전히 물리화**된다

> [!note] 발현 형태는 보스마다 제각각 (후속 기획)
> "삼켜서 똑같이 흉포해진다"는 식의 획일적 변신이 아니라, **어사이드마다 발현 방식이 다르다.**
> (예: 누구는 거대화, 누구는 분열, 누구는 주변을 잠식, 누구는 본체와 분리되어 싸움 등)
> → 구체적 발현 형태는 **보스별 개별 기획 단계에서** 캐릭터 특색에 맞게 설계.

> [!tip] 보스전의 진짜 의미
> **보스전 = 그 캐릭터의 어사이드(욕망·상처의 화신)와 싸우는 것.**
> 싸우는 동안 그들의 *가장 깊은 소망과 억눌린 기억*이 드러난다 → 단순 전투가 아니라 **그 사람의 내면을 들여다보는 과정**.

### 자아 (일부 잔존) — 비극의 핵심
- 타락해도 **자아가 완전히 사라지지 않는다.** 본인은 자기가 무엇이 되어가는지 어렴풋이 안다.
- 그래서 보스들은 **고통받고, 갈등하고, 때로 "멈춰 줘"라고 애원**한다.
- → 버터가 그들을 베는 것은 **살해이자 동시에 구원**이다. (다크하지만 따뜻한 잔혹함)
- **게임 연출**: 보스전 중 절규·대사 / 감정이 만개하는 2페이즈 / 약점 = 개화 부위

### 비주얼 모티브
- 검은 개화(꽃·가시·뿌리)가 몸에서 솟아 잠식. **감정별로 색·형태가 다름**
  (예: 공포=창백한 가시, 분노=붉게 타는 가시, 집착=결정처럼 굳은 꽃, 절망=시든 넝쿨)

### 피어난 감정 → 타락 유형 (보스 분류 기준)
| 유형 | 피어난 감정 | 모습 | 예시 |
|---|---|---|---|
| **① 광기** | 공포 | 죽음의 공포에 정신이 무너져 폭주 | 셰이디 |
| **② 집착** | 상실·거부 | 죽음/상실을 거부하며 끔찍한 짓(타인을 제물로) | 다야·디아나 |
| **③ 허무** | 절망 | 허무에 물들어 타락한 세계수 편에 섬 | 림·실라·네르 |

→ 보스 사연 작성 공식: **"이 캐릭터의 핵심 욕망/감정은? → 죽음 앞에서 어떤 부정 감정이 피어나 어떻게 비틀리나?"**

## 주인공: 버터 (Butter)

> 자세한 스펙은 [[notes/Project_New/캐릭터_버터.md|캐릭터 기획]] 참고 (작성 예정)

- **정체**: **수인(골든 리트리버).** *정사 캐릭터 '버터'를 다크하게 재해석한 주인공* (오리지널 아님)
- **비극 (마을의 멸망)**: 세계수가 폭주하고 몬스터가 밀려들 때, 수인 마을 동족이 전멸. **버터와 코미(어린 수인 동료) 단 둘만 살아남았다.** *(버터·코미는 정사에서도 함께 언급되는 어린 수인 → 정사 정합성 높음)*
- **이후**: 버터와 코미는 함께 성장하며 죽음이 퍼진 이 세계에서 살아간다.
- **목표**: **세계수를 죽이는 것.** 모든 비극의 근원을 끝내기 위해.
- **아이러니**: 죽음을 만든 세계수를 *'죽인다'* — 죽음으로 죽음의 근원을 끝내는 역설.

> [!warning] 최대의 비극 — 코미가 수인 보스가 된다
> 단 둘뿐인 생존자 **코미**가, 모종의 이유(인질로 잡힘 / 강제 개조 등)로 **수인 보스**가 된다.
> → 버터는 **마지막 가족 같은 동료를 자기 손으로 베야 하는** 운명에 직면. 타락 시스템의 "살해이자 구원"이 가장 아프게 작동하는 지점. (자세히는 [[notes/Project_New/보스라인업.md|보스 라인업]])

> [!warning] 규약 준수 (중요)

> - **그림·모델·음악은 전부 새로 제작** (원작 에셋 추출·트레이싱 금지)

## 핵심 줄거리 흐름 (초안)

1. **시작** — 버터, 동족이 전멸한 폐허에서 홀로 깨어남. 세상에 막 죽음이 퍼지는 시기.
2. **각성** — 모든 비극의 근원이 **죽음을 삼켜 타락한 세계수**임을 알게 됨.
3. **여정** — 세계수에 다가가는 길목에서, 타락한 존재(보스)들과 싸우며 진실을 모음.
4. **진실** — 세계수가 *왜* 죽음을 삼켰는지(공포)와 타락의 전말이 밝혀짐.
5. **결말** — 세계수의 핵을 부숨 → 세계가 끝남 → 버터, 차원문으로 홀로 탈출 (아래 「결말」 참고)

## 세계수를 죽이는 방법

> [!warning] 정사: 세계수 엘드르의 본체 = 엘리아스 세계 그 자체
> 보이는 나무/인간형은 **대화용 아바타**. 진짜 본체는 **세계 전체.**

- **죽이는 법**: 세계수 본체(아바타) 안의 **핵(심장)을 파괴.**
- **대가**: 세계수 = 세계이므로, **핵을 부수면 이 세계도 함께 끝난다.** → 그래서 버터는 죽이는 즉시 **탈출해야 한다.**
- **무기 = 도끼 (정사)**: 세계수를 벨 수 있는 **마법 도끼**가 정사에 실존, 현 소유주 = **네르(사제장 신물).** → 버터가 **네르전에서 도끼를 얻어** 세계수로 향하는 전개 가능.
- **맵 구조 = 잔나무 거점 (정사)**: 세계수의 힘은 각 종족 구역의 **작은 나무(잔나무)**로 분산·중계됨. → **각 종족 지역의 잔나무를 그 종족 보스가 지키는** 구조. 보스를 쓰러뜨려 거점을 끊고 핵에 도달.

## 결말 — "차원을 건너다"

> [!tip] 다크 IF의 유일한 생존자가 정사 세계로 넘어간다
> IF와 정사를 잇는 **메타 엔딩.**

```
엘레나 + 에슈르가 차원문 기술 개발 (정사: 둘은 차원 게이트 제작 전적)
   → 원래 계획: 죽음의 세계를 버리고 다른 차원으로 탈출
   → 스토리 끝: 세계수의 핵을 파괴 = 이 세계의 종말
   → 버터만 극적으로 차원문에 올라타 차원 이동
   → 도착한 곳 = 정사 본편의 트릭컬 세계 (죽음이 없는 원래의 엘리아스)
```

- **여운**: 모든 것을 잃은(코미 포함) 버터가, **죽음이 없는 평화로운 정사 세계**에 홀로 도착 → 비극 끝의 한 줄기 빛(혹은 또 다른 시작).
- **정할 것**: 엘레나·에슈르·비비 등 동료의 최후(희생? 잔류?), 버터가 *혼자만* 넘어가는 이유, 정사 세계 도착 후의 여운 톤.

# 캐릭터 — 버터 (Butter) [재정립 v3]

> [!info] 이 문서는?
> 트릭컬 팬게임 주인공 **버터**를, **정사 설정 + 새 세계관**에 맞춰 재정립한 기획입니다.
> 세계관: [[notes/Project_New/세계관_멀티버스IF.md|"죽음을 삼킨 세계수"]] / 동료·보스: [[notes/Project_New/보스라인업.md|라인업]]
> ※ 버터 = 정사 수인 캐릭터의 다크 재해석.

---

## 한 줄 정체성

> **원래는 누구보다 발랄하고 천진했던 강아지 수인. 그러나 마을이 멸망하고 — 함께 여정하던 단 하나의 친구 '코미'를 잃으면서 — 감정을 닫고 차갑게 식어버린 복수자.**

---

## 핵심 — 버터의 심장 ★

> [!tip] 모든 것이 여기서 나온다
> - **변화의 축**: *발랄한 천사 → 차갑고 어두운 복수자.* 그 **가장 큰 계기 = 코미 상실.**
> - **핵심 감정**: 복수와 종결 (코미와 마을을 앗아간 세계수를 끝낸다)
> - **닻**: 코미. 코미가 곧 버터의 따뜻함이었고, 코미를 잃자 그 따뜻함도 죽었다.

### 정사에서 가져온 두 기둥 (재해석)
| 정사 | 우리 게임에서의 의미 |
|---|---|
| **옐로카드** — 버터가 참는 한계(스택 100) | → **버서커 모드 각성기**의 게이지로 재해석. 분노가 쌓여 가득 차면 폭주 각성 *(정사의 '난폭한 자아 마가린'은 옛 밈이라 제외 — 별도 인격 없이, 버터 본인이 분노로 폭주하는 버서커)* |
| **어사이드 = 코미** — 정사에서 버터의 어사이드(마음의 실체화)는 '처음 사귄 친구' = **코미의 모습** | → 코미 = 버터의 **닻**. 그래서 **코미가 보스가 되는 것 = 마지막 닻이 적이 되는 것**. 이중의 비극 |

> 💡 **하나로 꿰임**: 코미가 버터를 인간답게 붙잡아왔다 → **코미를 잃자 분노를 억누를 제동장치가 사라졌다.** 게임 전체가 *버터가 분노(버서커)에 잡아먹혀 가는 과정*이 된다.

---

## 페르소나 (성격 · 동기 · 배경)

### 성격 — "식어버린 천사"
- **과거(정사)**: 한없이 발랄·천진·상냥. 대가 없이 모두를 돕는 천사. 똑똑하지만 친구를 의심할 줄 모르는 순수함.
- **현재(다크)**: 그 따뜻함을 **스스로 닫아버림.** 차갑고 무자비, 목표만 본다. → 정사의 밝음이 *죽은 채로 남아* 가끔 흔적만 새어나오는 대비가 비극.
- **분노**: 차가운 가면 아래 슬픔과 분노가 들끓는다. 한계를 넘으면 **버서커**로 폭주 — 이제 코미라는 제동장치가 없다.

### 동기
- **복수와 종결**: 코미와 마을을 앗아간 세계수를 자기 손으로 끝낸다.
- **이면**: 코미를 구하지 못한 죄책감 / 되찾고 싶은 마음이 복수의 진짜 연료.

### 배경 스토리 (★ 게임 시작 전 = 프롤로그/설정)
1. 발랄한 버터, **코미와 단짝**. 평화로운 수인 마을.
2. **세계수 폭주 → 죽음 역류 → 마을 침공/동족 몰살.** 둘은 함께 살아남아 여정에 오름.
3. **여정 중 전투에서, 세계수의 몬스터들에게 코미를 빼앗긴다** (끌려감 → 보스화의 시작 — 가장 큰 계기) → 버터, 완전히 차갑게 식음.

> → **게임 본편은 여기(코미 상실) 이후부터 시작.** 함께한 여정은 *플레이가 아니라 배경 설정*으로 둔다. 코미는 **후반에 보스로 재회.**

## 캐릭터 아크 (게임 본편)

1. **시작** — 이미 코미를 잃고 식어버린 복수자. 맨손 격투로 타락한 보스들을 벤다.
2. **상승** — 전진하며 점점 **버서커 각성기에 의존.** 자신을 잃어간다.
3. **위기** — **코미가 보스로 나타난다.** 마지막 닻이 적이 되어 눈앞에 선다.
4. **절정** — 분노(버서커)가 버터를 삼키려 한다. 버터는 *자기 안의 야수*와, 그리고 코미와 싸운다.
5. **결말** — 세계수의 핵을 부수고, 모든 것을 잃은 채 **차원문으로 홀로 정사 세계로 넘어간다.** → [[notes/Project_New/세계관_멀티버스IF.md|결말]]

### 🆕 버서커 모드 (각성기 / 궁극기)
- 옐로카드(분노) 100 충전 → **버서커로 폭주하는 일시 각성기.**
- 효과: 이동·공격 속도·공격력 대폭↑ / 슈퍼아머 / 전용 어빌리티 / 거칠고 야수 같은 모션
- **서사적 리스크**: 강력하지만 *버터가 자신을 잃어가는* 위험한 힘. (코미라는 닻이 사라진 뒤로 더 깊이 빠져든다)

### 전투 진행 (맨손 → 무기 습득)
> 정사 버터는 새총을 쓰지만, 다크 액션에 맞춰 **맨손 격투 → 무기 습득** 노선으로 재해석.

- **1단계 — 맨손 격투(기본)**: 수인 야수성. 4타 콤보(잽→할퀴기→바디블로/돌진→피니시). 빠르고 유연
- **2단계 — 무기 습득**: 스토리 진행하며 무기 획득
  - 데모 무기 = **도끼**(느리지만 데미지·밸런스 파괴 강함). 3타 콤보 + 차징 올려치기(공중연계) + 저스트 패링→카운터 내려찍기
  - *연결 고리*: "수인 촌장의 도끼"는 정사상 **디아나(촌장)**의 것 / 세계수를 벨 신물 도끼는 **네르** 소유 → 무기 입수를 스토리와 엮을 여지

### 방어·스탯
- **패링**: 데미지 100% 무효 + 적 밸런스 대폭 소진(그로기) + 자원 충전 / **회피**: I-frame + 반격 + 자원 충전
- 스탯: 공격력·방어력·치명타·**밸런스 파괴력**(그로기 유발 — 스텔라 블레이드 Balance 참고)

> *(참고: 디아나는 수인 슬롯에서 빠짐 — 컷 / 특수보스 / 후속 등장 중 택 1, 미정)*
> 🕵️ **뮤트 = 회색지대**: 버터처럼 *세계수를 없애려는* 목적은 같지만, "엘프만 살리고 세상은 버린다"는 이기적 동기 → 같은 목표, 다른 신념의 충돌.
> 💎 **다야 = 완벽의 붕괴**: 다이아몬드(영원·불변의 상징)인 그녀에게, 죽음=부패=불완전은 가장 큰 공포. *"완벽한 나"가 죽음 앞에 균열나는 것*을 못 견뎌 ②유형으로 타락. 전투도 "균열(밸런스 파괴)을 내야만 무너지는" 강벽 컨셉과 직결.
> 🔗 **다야 ↔ 비비(동료)의 악연**: 정사에서 비비는 *세계수를 수은으로 죽이려는 실험*으로 다야에게 수은 든 선물을 했다 → 죄책감에 폭언하고 도주. → **동료 비비가 보스 다야에게 과거 상처를 준 가해자**라는 드라마. 다야전에서 비비의 죄책감 서사가 터질 수 있음.

## 종반부 피날레 (요정 → 세계수)

요정은 **세계수 교단의 핵심 종족**. 그래서 교단 수뇌부를 거쳐 세계수에 도달하는 **3단 피날레**로 배치.

```
네르 (신앙) → 에르핀 (혈육) → 세계수 (신 자체)
```

| 순서 | 보스 | 정사 | 타락/역할 | 비극 포인트 |
|---|---|---|---|---|
| **1** | **네르** (요정/사제장) | 세계수 교단의 **실질적 권력자**, 깐깐·진지. **세계수 벨 도끼(신물) 소유** | ③ — **신념으로 타락한 세계수를 수호** | 신을 가장 굳게 믿었기에 타락마저 끌어안고 막아섬 / **버터가 여기서 도끼 획득** |
| **2** | **에르핀** (요정/여왕) | **세계수가 직접 탄생시킨** 여왕. 막강한 마력·무력(티그를 한 방에 제압). 평소 허당이나 한계 상황엔 비범 | ② or ③ — 세계수의 **분신/혈육** | 세계수가 가장 사랑한 존재. 그녀를 베는 것 = 세계수의 마음을 베는 것 |
| **3 (최종)** | **세계수 (타락)** | 죽음을 삼켜 뒤틀린 만물의 근원 | — | 죽음이 두려워 발버둥 친 가엾은 신. 동정과 증오의 최종전 |

> [!tip] 피날레의 잔혹함
> 세계수에 다가갈수록 버터는 **"세계수가 가장 사랑했고, 세계수를 가장 사랑한 존재들"**(네르의 신앙, 에르핀의 혈육)을 차례로 베어야 한다. 목표에 가까워질수록 더 무거워지는 구조.

- **추정 표시**: 시온 "죽음의 유령"은 커뮤 루머(정사 단서 없음), 셀리네 "옛 군주" 경위는 정사 불명

# 트릭컬 2차 창작 규약 — 확인 노트

> [!info] 이 문서는?
> 트릭컬 리바이브 팬게임을 만들 때 **원작사 규칙을 어기지 않으려면 무엇을 지켜야 하는지** 정리한 문서입니다.
> 한 줄 결론: **"무료로 배포하고, 그림·음악은 직접 만들고, 성적·혐오 표현만 피하면 OK."**
> 전체 그림은 [[notes/Project_New/00_프로젝트 현황.md|프로젝트 개요]]를 먼저 보세요.

> 원문: 에피드게임즈 공식 FAQ (25.03.04판, 예고 없이 변경 가능 → 주기적 재확인 필요)

---

## 0. 본 프로젝트 확정 방향

- **루트**: **1번 — 무료 배포 / 비상업** (가장 안전)
- **컨셉**: 트릭컬 **멀티버스 IF** — 정사 캐릭터들의 차원별 변주 + 오리지널 캐릭터 **버터**
- **톤**: **다크** (잔혹·비극 허용 범위 내)
- **기술**: UE5 + GAS (ProjectKD 자산 재활용)

→ 이 방향은 규약 안에서 **전면 허용**됨.

---

## 1. 핵심 요약

| 구분 | 내용 |
|---|---|
| **게임 IP** | 세계관·스토리·캐릭터·몬스터·이미지·BGM·영상 등 일체 = 에피드 소유 |
| **기본 태도** | 2차 창작 **적극 장려**. 비영리 + 일부 영리 허용 |
| **무료 배포** | 비상업·교류 목적 무료 배포 = **자유롭게 OK** ✅ |
| **개인 직접판매** | 제3자 유통망(온라인몰 등) 안 거치고 개인 직접판매만 영리 가능. 월 누적 500개 초과 시 서면동의 |
| **동인 모임** | 최대 5명까지 교환 허용. 초과 시 서면동의 |
| **사업자** | 영리 판매 전 반드시 서면동의 |
| **방송/SNS** | YouTube·Twitch 등 공정이용 범위 내 광고·후원 수익 OK |

## 2. 제작 시 금지 사항 (위반 = 법적 책임)

- 공서양속 위반 / 제3자 권리침해 / 명예훼손
- 허위·음란·위협·불쾌감·회사 이해관계에 어긋나는 내용

- **공식 콘텐츠로 오인**될 내용
- **IP 원본 그대로 사용·복제, 또는 일부만 수정·각색·트레이싱(창작성 부족)**
- 공식 로고(회사/게임) 사용

## 3. 게임(소프트웨어)에 적용한 결론

| 🚫 | **캐릭터 훼손 주의** | 조롱·성적 소비 목적 훼손 금지 (단, 비극화는 OK) |

## 5. 다크 톤 — 허용 범위 (★ 자주 헷갈림)

**핵심: 다크 ≠ 혐오. 잔인함은 톤이지 위반이 아니다.**

```
다크 세계관·잔혹·고어·죽음·학살·타락·절망  → ✅ 허용 (정사도 다크함)
정사 캐릭터 비극화 (죽음/타락/악역화)        → ✅ 허용
─────────────────────────────────────────
음란 (성적/R18 콘텐츠)                      → 🔴 금지 (별도 명시 항목)
현실 집단 혐오 (인종·성별·종교 차별/증오)    → 🔴 금지
캐릭터 조롱·비하·성적 소비                   → 🔴 금지
```

**판단 기준**:
- 규약의 "혐오" = **현실 집단 차별**을 뜻함. 어두운 분위기·잔혹 서사는 해당 X
- 잔인함은 **"맥락(서사·연출)이 있으면 전부 OK"**. 자극만을 위한 무의미한 과잉만 주의
- 캐릭터: **"비극이냐(OK) vs 조롱이냐(NO)"**로 구분

> **결론 한 줄**: 잔인 ✅ / 다크 ✅ / 성적·현실혐오·조롱 ❌

# 버터 — AI 이미지 생성 기록 (프롬프트)

> [!info] 이 문서는?
> 버터 최종 디자인 4컷을 **어떻게 만들었는지** 기록한 문서입니다. 같은 결을 다시 뽑거나, 다른 캐릭터에 응용할 때 참고.

## 도구 / 설정

| 항목 | 값 |
|---|---|
| **플랫폼** | Higgsfield |
| **모델** | **Seedream 4.5** (`seedream_v4_5`, ByteDance) — 4K, 정밀 제어, 레퍼런스 입력 지원 |
| **품질** | high |
| **비율** | 단독 컷 = `1:1` (복제 방지에 유리) / 턴어라운드 시트 = `16:9` |
| **핵심 기법** | **레퍼런스 이미지 고정** — 마음에 든 컷을 업로드해 `medias`(role: image)로 입력 → 얼굴·체형·복장 일관성 확보 |

> 작업 순서: 텍스트로 디자인 탐색 → 마음에 든 컷을 레퍼런스로 업로드 → 그 레퍼런스 기준으로 후드 ON/OFF·정면/후면 파생.

## 최종 4컷 프롬프트 (영문, 그대로 복붙용)

> 공통: 레퍼런스 이미지(OFF 정면)를 `medias`로 함께 입력.

# 3D 에셋 파이프라인 — Meshy → UE5

> [!info] 이 문서는?
> AI(Meshy)로 버터 메쉬를 뽑은 **다음에 해야 할 작업들**을 순서대로 정리한 파이프라인입니다.
> 캐릭터 디자인(턴어라운드) → [[notes/Project_New/캐릭터_버터.md|버터 노트]]

> [!warning] 큰 그림
> AI는 **메쉬 + PBR 텍스처 + (대략적) 토폴로지**까지 만들어줍니다. 하지만 게임에 쓰려면 **리토폴로지·UV·텍스처 베이크·리깅**을 거쳐야 깔끔합니다. AI 결과물은 보통 **80% 완성, 20%는 수동 보정** 필요(정상).

---

## 전체 흐름 (한눈에)

```
1. 생성(Meshy, 이미지→3D, T포즈)
   → 2. 리토폴로지 + UV (Remesh / 외부 RetopoFlow·ZBrush)
   → 3. 텍스처(PBR) 베이크·재적용
   → 4. 리깅(오토리그, T포즈, Mixamo 호환)
   → 5. 익스포트 (GLB 권장 / FBX scale 0.01)
   → 6. UE5 임포트 → 머티리얼·노멀·리그 검증 → LOD(Nanite)
```

---

## 단계별 상세

### 1. 생성 (Meshy)
- **입력**: 우리 버터 **턴어라운드(정면/측면/후면)** 이미지. 멀티이미지 입력 가능 → 정확도↑
- **포즈**: 반드시 **T포즈 또는 A포즈**로 생성 (리깅 도구가 기대하는 시작 자세)
- **출력**: 풀컬러 텍스처 메쉬. FBX/GLB/OBJ/BLEND 등 익스포트

### 2. 리토폴로지 + UV (게임레디의 핵심)
- AI 메쉬는 보통 **삼각형 덩어리(밀집)** → 게임엔 부적합. **클린 쿼드**로 재구성 필요
- **간편**: Meshy 내장 **Remesh** (쿼드 토폴로지 + 관절 엣지루프 + UV 재전개 + 폴리수 조절)
- **정밀(히어로용)**: 블렌더 **RetopoFlow** 애드온 / Maya **Quad Draw** / ZBrush **ZRemesher**
- ⚠️ 리토폴로지하면 **UV가 새로 필요** → 다음 단계에서 텍스처 재적용

### 3. 텍스처 / PBR
- Meshy 자동 PBR 맵: **알베도·노멀·메탈릭·러프니스·AO**
- ⚠️ 리토폴로지로 UV가 바뀌면 → **고폴리→로폴리 텍스처 베이크** (Blender Cycles → Bake: Diffuse/Normal) 또는 Meshy에서 **AI Texturing 재실행**
- 💡 **GLB로 내보내면 PBR 채널이 가장 잘 보존됨** (블렌더 머티리얼 노드 자동 연결)

### 4. 리깅 (오토리그)
- **Meshy 오토리그**: 휴머노이드/바이페드/스타일라이즈 자동 본 배치 (30초, T포즈 기준)
- **대안(품질↑/Mixamo 호환)**:
  - **AccuRIG 2** (Reallusion) — AI 오토리그, 휴머노이드+논휴머노이드
  - **Tripo AI** — 업로드→자동 리그, 왜곡 적은 웨이트
  - **3D AI Studio** — GLB 업로드→ Mixamo 호환 리그
  - **Mixamo** — FBX/OBJ 드래그→ 관절 마커→ 표준 스켈레톤
- ⚠️ 극단 포즈에서 살짝 뒤틀림 = 정상. 스킨 웨이트 수동 보정

### 5. 익스포트
- **GLB** = PBR 보존 최선 (간편 경로 추천)
- **FBX** = 표준. **Scale 0.01** 설정(게임엔진용) + 노멀 정상 확인
- 본 계층이 업계 표준이라 애니메이션 리타겟 깔끔

### 6. UE5 임포트
- FBX/GLB 임포트 → **머티리얼·노멀·리그** 검증
- **LOD**: AI 툴엔 LOD 자동 생성 약함 → **UE5 내장 Auto-LOD / Nanite**로 처리
- Meshy 등은 **UE 네이티브 플러그인**도 제공 (직접 임포트)

## B. Meshy 설정 (Meshy 6)
- **입력**: Text-to-3D / Image-to-3D / **Multi-view(2~4장, 유료)** ← 버터 턴어라운드용
- **Model Type**: Standard(디테일) / Low Poly(게임)
- **Pose**: A/T/Custom (리깅하려면 T·A 필수)
- **Polycount(Remesh)**: 100~300,000, 쿼드↔삼각형 전환
- **Texture**: 텍스트/레퍼런스이미지/프리셋 → PBR(Diffuse·Rough·Metal·Normal·Emission), 2K~4K
- **Rigging**: 오토리그(휴머노이드/크리처) + 모션 600+(Pro)
- **Export**: FBX·OBJ·**GLB**·USDZ·STL·BLEND·3MF
- **라이선스**: 무료=CC BY 4.0(출처표기+공개 의무) / 유료=에셋 소유권 본인 ← **팬게임 비공개면 유료**
- *대칭(Symmetry) 토글은 문서상 불명 → 블렌더 미러로 처리*

## C. 게임 캐릭터 스펙 기준
| 항목 | 모바일 | PC/콘솔 |
|---|---|---|
| 폴리(tris) | 1,500~5,000 | **15,000~50,000** |
| 텍스처 | 512~1K | 2K 표준 / 4K 히어로·얼굴 |
- **PBR(사실체)**: BaseColor·Normal·Metallic·Roughness·AO (ORM 팩)
- **NPR(셀셰이딩)**: 디퓨즈+라이트맵 마스크+램프+**얼굴 SDF맵**+아웃라인 → 머티리얼 존 분리 핵심
- 본: 휴머노이드 ~50~65(Mixamo) + 귀/꼬리/천 흔들림 본 / LOD: UE5(Nanite는 스켈레탈 미지원)
- **진짜 병목 = 폴리보다 텍스처 VRAM**

## D. 버터 추천 스펙 (PC 셀셰이딩 플레이어블)
```
입력: Image-to-3D + Multi-view (턴어라운드 4장)
Model Type: Standard / Pose: T-Pose
Polycount: 30,000~40,000 쿼드 (데모 15~30k)
Texture: 바디 2K~4K / 얼굴 별도 2K / 머리·천 별도
Export: GLB(PBR 보존) → UE5
셰이딩: UE5 Toon/NPR (램프·SDF·림·아웃라인)
```

## E. NPR(원신/명조) 셰이딩 핵심
램프 2단 셰이딩 · 얼굴 SDF 섀도 · 림라이트 · 블루 앰비언트 섀도 · 헤어 스펙큘러 · 인버티드 헐 아웃라인.
→ 메쉬는 공용, **머티리얼만 사실체/카툰 스왑** 가능. 상세는 [[notes/Project_New/캐릭터_버터.md|버터 노트]].

## F. Meshy MCP (클로드 직접 연동)
- 공식 **`@meshy-ai/meshy-mcp-server`** (npm). 도구: text/image/multi-image→3D, refine, remesh, retexture, rig, animate
- 세팅: Meshy API 키(`msy_...`) 발급 → 클로드 MCP 설정에 추가
```json
{ "mcpServers": { "meshy": { "command": "npx",
  "args": ["-y","@meshy-ai/meshy-mcp-server"],
  "env": { "MESHY_API_KEY": "msy_YOUR_API_KEY" } } } }
```
- ⚠️ MCP 호출 = REST 호출 = **크레딧 차감(웹과 동일)**. 유료 플랜이라야 멀티뷰·고폴리·소유권
- **MCP라고 품질이 오르진 않음** (같은 Meshy 엔진). 품질은 입력·설정·플랜이 좌우

## G. 블렌더 후처리 가능 범위 (Meshy 후)
- **외모/형태**: 메쉬 편집·스컬프트, 비율, 얼굴·손·귀·꼬리 다듬기/리모델
- **머티리얼/텍스처**: 부위별 머티리얼 슬롯 분리(피부/머리/천/금속) + 각 PBR맵 편집·교체·페인트·베이크
- **UV** 재전개 / **리깅·웨이트** 수정 / **노멀·스케일·정리** / FBX·GLB 익스포트
- = AI 메쉬 후처리는 블렌더로 사실상 전부 가능

## H. 캐릭터 아트 제작 프로세스 (상세)
| 단계 | 무슨 작업 | 도구 |
|---|---|---|
| ① 컨셉아트(2D) | 그림으로 디자인 확정(턴어라운드·색·실루엣) | PS/AI |
| ② 블록아웃/베이스 | 기본 도형으로 대략 형태·비율 | Blender/ZBrush (←AI가 대체) |

| ④ 리토폴로지 | 형태 유지+깔끔한 로우폴리 쿼드로 재구성, 관절 엣지루프 | Blender/Maya |

## I. 쿼드 vs 삼각형 (리토폴 핵심)
- **만들 땐 쿼드, 렌더링은 삼각형** — GPU는 삼각형만 그림, 근데 쿼드1개=삼각형2개라 자동 변환
- **쿼드로 만드는 이유**: 관절 변형 깔끔 / 섭디비전 작동 / 엣지루프 편집 / UV·리토폴 쉬움
- **버짓은 tris로** 셈 (GPU 단위). 쿼드 1.5만 = 3만 tris
- 실무: 쿼드 작업 → **익스포트 직전 삼각화(Triangulate)** 권장
- **리토폴 = 무겁고 지저분한 메쉬를, 형태 유지하며 움직이기 좋은 깔끔한 쿼드 메쉬로 새로 짜는 것.** 핵심은 **엣지 흐름**(관절·눈·입에 루프)

# AI 메쉬 → 블렌더 정리 (실전 레시피)

> [!info] 이 문서는?
> AI(Meshy/Rodin)로 뽑은 **지저분한 삼각형 메쉬**를 블렌더에서 **깔끔한 로우폴리 + 텍스처**로 만드는 실전 순서. (유튜브 튜토리얼 Watch 분석)
> 우리 Rodin FBX(`ffc0e5b3...`)에 그대로 적용 가능.

> [!warning] 핵심 원리
> **AI 메쉬는 삼각형 난잡 → 폴리 줄이면 텍스처가 깨짐 → 그래서 "하이폴리에서 로우폴리로 텍스처를 베이크"** 하는 게 전체의 핵심.

---

## 0. 준비
- AI에서 생성 후 **`.blend`(또는 FBX/GLB)** 다운 → 블렌더 열기
- 뷰포트: **Material Preview**(텍스처) + **Statistics**(폴리수) + **Wireframe**(메쉬 상태) 켜기 → 삼각형 난잡 확인
- **모델 복제 2개** → `high poly`(원본 유지, 나중에 베이크 소스) / `low poly`(작업본)

## 1. 폴리 줄이기 (2가지 방법)

### A) Decimate 모디파이어 (빠름)
- `Modifier → Generate → Decimate → Collapse` → Ratio **0.05~0.01**
- 장점: 빠름 / 단점: **여전히 삼각형** → 애니메이션엔 부적합

### B) Remesh(Voxel) 방법 (깔끔, 권장)
- **Sculpt 모드** → 상단 **Remesh → Voxel Size ~0.02** → **Ctrl+R** 적용
- 장점: 균일한 깨끗한 메쉬 / 단점: **텍스처가 다 깨짐**(이상한 선) → 아래 베이크로 복구

## 2. 로우폴리 새 UV + 새 텍스처 만들기
1. `Data Properties → UV Maps` → 기존 UV **삭제** → **새 UV Map 생성**
2. 기존 텍스처 삭제 → **새 머티리얼 + 새 Image Texture**(2K 또는 4K, 새 이미지 생성)
3. 셰이더: **Image Texture → Base Color** 연결 (검은색이라 아직 안 보임)
4. **Edit 모드 → 전체 선택 → `U` → Smart UV Project** (Island Margin **0.02**) → 새 UV 펼침

## 3. ★ 하이폴리 → 로우폴리 텍스처 베이크 (핵심)
> 하이폴리의 색 정보를 로우폴리 새 UV에 구워 넣는 단계.

**필수 조건**
- 하이폴리·로우폴리가 **같은 위치·같은 크기**여야 함 (N패널 Transform 확인)

**순서**
1. **하이폴리 먼저 선택 → 로우폴리 나중 선택** (로우폴리 = 활성 오브젝트)
2. 로우폴리: **새 UV맵 선택 + 새 Image Texture 선택**(머티리얼에서)
3. `Render Properties → 엔진 = Cycles`
4. **Bake** 항목:
   - **Selected to Active = ON**
   - **Bake Type = Diffuse**
   - **Influence: Direct·Indirect 체크 해제** (빛 말고 **색만** 굽기)
   - Margin ~16
5. **Bake** 실행

**아티팩트 뜨면 (얼굴 등 이상)**
- `Selected to Active → Extrusion` 값을 **0.05** 로 올리고 다시 Bake
- 이유: 하이/로우가 정확히 같은 위치라, 색을 쏘려면 약간의 바깥 여유(extrusion)가 필요

## 4. 완성
- 하이폴리 끄면 → **로우폴리 + 베이크된 깔끔 텍스처**
- Wireframe 확인 → 정돈된 메쉬 + 좋은 텍스처 → **애니메이션 가능**

---

## ⚠️ 한계 / 주의 (우리 케이스 보강)
- **Voxel Remesh는 "균일 토폴로지"지 "엣지루프 토폴로지"는 아님** → 빠른 결과엔 OK, **히어로 캐릭터·정밀 변형엔 수동 리토폴**(RetopoFlow)이 더 나음
- 얼굴·손·눈은 이 방법으로도 **여전히 약함** → 별도 보정 필요 ([[notes/Project_New/3D파이프라인_Meshy_to_UE5.md|블렌더 보정 체크리스트]] 참고)
- **셀셰이딩(원신/명조)** 목표면 이 베이크 텍스처는 베이스일 뿐, 룩은 UE5 NPR 셰이더

# UE5 셀셰이딩(NPR) 실전 — 머티리얼로 토온 룩 만들기

> [!info] 이 문서는?
> UE5에서 **원신/명조 같은 셀셰이딩**을 머티리얼(커스텀 HLSL 노드)로 만드는 핵심 기법. 카툰 art direction의 룩 90%가 여기서 나옴.

> [!tip] 핵심: 토온 룩 = 3가지 블록 조합
> ① 라이팅(Lambert) → ② 밴딩(2~3톤으로 끊기) → ③ 엣지(외곽/디테일)

---

## ① 라이팅 (Lambert) — 명암 만들기
- 커스텀 노드 코드: `light_intensity = max(dot(Normal, LightDir), 0)`
  - 입력: **Pixel Normal World Space** + **Sky Atmosphere Light Direction**(태양 방향)
- 결과: 회색 명암(밝음/중간/그림자)이 생김 → 이걸 끊을 재료

## ② 밴딩 (Cel) — 명암을 단계로 끊기 ★
- light_intensity를 **임계값으로 나눠 색을 배정** (= 램프 효과):
```hlsl
if      (light_intensity > 0.65)  color = Input3;  // 밝은 톤
else if (light_intensity > 0.25)  color = Input2;  // 중간 톤
else                              color = Input1;  // 그림자 톤
return color;
```
- → 부드러운 명암이 **2~3단 평면 톤**으로 → 셀셰이딩 특유의 면이 끊기는 느낌
- 임계값(0.65/0.25)·색 3개를 **파라미터**로 빼면 캐릭터별 조절 가능

## ③ 엣지 (외곽/디테일) — 노멀 변화로 선 뽑기
- `edge = length(ddx(Normal)) + length(ddy(Normal))`  (DDX/DDY = 화면상 변화율)
- 복잡한 메쉬의 **디테일/외곽선** 추출
- 파라미터: **thickness**(나누기), **contrast**(`(edge-0.5)*contrast`), `saturate()`로 0~1 클램프
- → 만화 같은 라인 효과

## 조합 & 적용
- 위 3개를 한 머티리얼에 합쳐 → **Material Instance**로 thickness/contrast/색/임계값 실시간 조절
- 포스트프로세스 머티리얼 또는 캐릭터 머티리얼로 적용

---

## 더 "원신답게" 하려면 (이 영상 + 추가)
이 영상은 **밴딩+엣지 기본**까지. 풀 원신/명조 룩엔 추가로:
- **램프 텍스처**(threshold 대신 그라데이션 텍스처로 명암 색 제어 — 더 예쁨)
- **얼굴 SDF 맵**(얼굴 그림자 깔끔하게)
- **아웃라인 패스**(인버티드 헐 또는 포스트프로세스 엣지 — 외곽 잉크선)
- **블루 앰비언트 섀도 + 림라이트**
→ 상세 기법은 [[notes/Project_New/캐릭터_버터.md|버터 노트 NPR 섹션]]

> 💡 1인 개발: 직접 짜기 부담되면 **마켓플레이스 토온 셰이더 에셋**(Ultra Hybrid Toon 등)으로 시작 → 위 원리 이해하고 커스터마이즈

# AI 없이 캐릭터 제작 (블렌더 수동 풀과정 실전)

> [!info] 이 문서는?
> AI를 안 쓰고 **블렌더만으로** 캐릭터를 처음부터 만드는 실제 작업 순서. (프로 아티스트 20분 풀과정 Watch 분석) — AI 파이프라인의 "원본"을 이해하는 용도.

> [!tip] 한 줄 철학
> "스컬프트 못 해도 일단 시작해라. 그림 잘 못 그려도 연필 들 수 있듯이." — 블록아웃은 **형태만**, 디테일은 나중.

---

## 1. 스케일 기준 (★ 처음에)
- **기본 큐브로 키 측정** → 월드 스케일 확립. (안 하면 나중에 다 틀어짐)

## 2. 블록아웃 (형태만, 디테일 X)
- **프리미티브(큐브·구·실린더)**를 회전·이동·배치해 부위별 기본 형태
- 순서: 머리 → 토르소 → 팔 → 손 → 다리 → 부츠
- **손**: 통째로 만들지 말고 **팜 + 손가락 5개 × 3마디**로 쪼개서 조립
- **Mirror 모디파이어**로 좌우 대칭

## 3. 리메시 + 스컬프트
- 모디파이어 적용 → **Sculpt 모드 → Remesh → 스무딩(Mesh Filter)** → 디테일 스컬프트
- 브러시: **Smooth, Mesh Filter, Scrape(샤프한 면 — 너무 부드러우면 어색, 샤프+소프트 대비), Clay Strips(근육 레이어), Mask**
- 부위를 **점진적으로 병합**(몸+다리, 머리+몸)
- **눈**: 구(sphere) + 미러 → 그 위에 **눈꺼풀 스컬프트**(즉각 피드백)

## 4. 옷 (★ 핵심 트릭)
- **캐릭터를 복제** → Sculpt 모드 → **Box Trim / Lasso Trim**으로 필요없는 부분 잘라냄
  - 하의 = 토르소 윗부분 잘라냄 / 상의 = 머리·팔·다리 잘라냄
- 남은 조각 = **몸에 딱 맞는 옷 베이스** → Remesh → Inflate(Mesh Filter) → 주름 스컬프트
- **얇은 것(모자)**: Plane으로 시작 → **Solidify 모디파이어**로 두께 (얇은 거 직접 스컬프트하면 망함)
- 옷끼리 **충돌(겹침) 체크** → 빼주기
- 💡 위험한 작업 전 **복제해서 backup 컬렉션**에 보관

## 5. 리토폴로지 (★ 디테일 유지 트릭)
> 하이폴리 → 애니메이션 가능한 로우폴리로, 디테일 안 잃고 옮기기
1. 하이폴리 복제
2. **Quad Remesher**(Exoside 애드온, X대칭, ~6,400 쿼드) → 로우폴리 (단 디테일 사라짐)
3. **Multires 모디파이어 + Shrinkwrap 모디파이어** 추가
   - Shrinkwrap **타겟 = 하이폴리**, Wrap Method = **Project + Negative 체크**(눈 아티팩트 방지)
4. Multires **섭디비전 레벨 ↑** → 하이폴리 디테일 복원
5. Shrinkwrap **Apply** → 디테일이 Multires에 베이크 → 렌더타임 디테일 유지
> 무료 대안: 블렌더 내장 Remesh / RetopoFlow 애드온

## 6. 머티리얼
- 부위별 베이스 머티리얼. **피부 = 색 + Subsurface Scattering + Specular 1.2~1.4**

## 7. 헤어 (파티클)
- **Particle System(Hair)** → 가이드 커브 몇 개 + **Interpolated Children**(250개 등)
- **Clumping + Roughness**로 모양, **Particle Sculpt**로 다듬기, **Vertex Group**으로 부위별
- 셰이딩: **Principled Hair BSDF** 한 노드면 충분

## 8. 리깅
- **Auto-Rig Pro**(애드온): 컨트롤 포인트 정렬 → **Match to Rig**
- 진짜 강점 = **오토 웨이팅**(블렌더 기본보다 훨씬 좋음) → 웨이트 페인팅 거의 안 함(눈 주변만 살짝)
> 무료 대안: 블렌더 내장 **Rigify** + 웨이트 보정

## 9. 마무리 + 포즈
- 퍼즈/디테일 추가 → 씬에 배치 → **포즈** → 카메라 앵글

---

## 🔑 AI 파이프라인과 비교 (왜 알아야 하나)
| 단계 | 수동 | AI 활용 |
|---|---|---|
| 블록아웃·스컬프트 | 프리미티브→리메시→스컬프트 (시간↑) | **Meshy/Rodin이 대체** |
| 리토폴 | Quad Remesher + Multires/Shrinkwrap | Remesh/Smart Lowpoly (자동) |
| 텍스처 | 수동 머티리얼/페인팅 | AI PBR |
| 리깅 | Auto-Rig Pro / Rigify | Meshy/Mixamo 오토리그 |
> **수동을 알면 AI 결과의 "어디가 잘못됐고 어떻게 고칠지"가 보임.** AI는 ②③를 압축할 뿐, 원리는 동일.

# 캐릭터 아트 제작 — 정석 파이프라인 (필수·함정·AI 활용)

> [!info] 이 문서는?
> 프로 캐릭터 아티스트가 따르는 **표준 제작 순서**와, 단계별 **꼭 할 것 / 조심할 것**, 그리고 **AI로 어디를 압축**할 수 있는지 정리. AI 활용 정상 파이프라인을 직접 짜기 위한 기준.

> [!warning] 대원칙 3가지
> 1. **앞단(컨셉·베이스)은 AI로 압축, 뒷단(토폴로지·텍스처·리깅)은 사람이 마무리** — "AI로 다 끝"이 아님
> 2. **토폴로지가 가장 간과되는데 가장 중요** (프로 코스들이 공통 강조)
> 3. **실루엣이 전부** — 모든 단계에서 실루엣을 망치지 마라

---

## 0. 레퍼런스 보드 (★ 무조건 먼저)
- **필수**: 모든 프로젝트는 레퍼런스 보드부터. "필요할 모든 것"을 모음(포즈·복장·재질·색·실루엣)
- **함정**: 레퍼 없이 바로 만들기 → 중간에 헤매고 재작업 폭증
- **AI**: 우리 버터 턴어라운드/컨셉이 이 역할 ✅

## 1. 컨셉아트 (2D)
- **필수**: 최소 **정면·측면·3/4** + **얼굴·손·장비 클로즈업**. 컨셉이 상세할수록 모델링 질문↓
- **함정**: 컨셉 부실하면 모델러가 즉흥 → 비율·디자인 흔들림
- **AI**: Seedream 등으로 생성 (우리가 한 것). *형태 결정의 90%*

## 2. 스케일 세팅 (★ 처음에)
- **필수**: **작업 시작 시 키(예 185cm) 박스 기준** 잡기. (Maya cm 단위 → 박스 → OBJ → ZBrush 가이드)
- **함정**: 스케일 나중에 맞추면 **리깅·엔진에서 전부 틀어짐** (FBX 0.01 문제와 연결)

## 3. 블록아웃
- **필수**: 디테일 없이 **실루엣·비율·덩어리**부터. ZBrush 다이나메시 구체로 빠르게 "3D로 컨셉"
- **함정**: 블록아웃에서 비율 안 잡고 디테일 들어가면 → 나중에 다 엎음

## 4. 하이폴리 스컬프트
- **필수**: 매력적 비율·표정·머리카락·천 주름·하드서피스(ZModeler/DynaMesh)
- **함정**: 스타일라이즈도 **스컬프트 디테일 소홀하면 밋밋**. 좌우 대칭 관리
- **AI**: **Meshy/Rodin이 블록아웃+스컬프트를 압축** (베이스 메쉬 생성)

## 5. 리토폴로지 (★ 가장 중요·가장 간과)
- **필수**: 하이폴리 위에 **클린 쿼드 로우폴리** 재구성. **관절(어깨·팔꿈치·무릎)·눈·입에 엣지루프**. 큰 폴리부터 → 실루엣 유지하며 분할
- **함정**: 엣지 흐름 없으면 **애니메이션 때 찌그러짐**. 삼각형/n-gon 남발, 실루엣 손상
- **AI**: Meshy **Remesh** / Rodin **Smart Low-poly**(쿼드+폴리수+노멀베이크) 자동 → 단 **히어로는 수동 보정**

## 6. UV 언랩
- **필수**: 솔기(seam) 잘 잡고 UV 아일랜드 배치. Maya UV 에디팅 워크스페이스(뷰포트+UV 동시)
- **함정**: UV 낭비·**텍셀 밀도 불균일**(어디는 선명, 어디는 흐림)

## 7. 베이킹
- **필수**: 하이→로우 디테일을 **노멀·AO 맵**으로 구움. (Substance/Marmoset)
- **함정**: **베이킹 아티팩트**(케이지·솔기·웨이브). Photoshop으로 수정하는 게 일반적

## 8. 텍스처링
- **필수**: PBR(BaseColor/Rough/Metal). **분할 작업 권장** — 보통 ① 머리+손 ② 옷 ③ 소품 3프로젝트로 나눔
- **함정**: 한 텍스처에 다 욱여넣기 → 해상도·관리 지옥
- **AI**: Meshy 자동 PBR(사실체). **셀셰이딩(원신/명조)은 텍스처보다 UE5 NPR 셰이더가 핵심**

## 9. 리깅 / 스키닝 / 웨이트
- **필수**: 스켈레톤 + **웨이트 페인트**(뼈가 피부 끌어당기는 정도). T/A포즈에서 시작
- **함정**: **어깨·골반·목·손가락** 변형 깨짐. 극단 포즈 핀칭
- **AI**: Meshy/Tripo/Mixamo **오토리그** (T포즈 필수). 단 웨이트 미세보정은 수동

## 10. 페이셜 (필요 시)
- **필수**: 표정용 블렌드셰이프/얼굴 본. (애니 캐릭은 키프레임 애니 전제)
- **함정**: 눈·입 토폴로지 없으면 표정 못 만듦 → 4·5단계에서 미리 고려

## 11. 엔진 통합 + 셰이더 + LOD
- **필수**: UE5 임포트 → 머티리얼(PBR/**NPR 토온**), LOD, **FBX scale 0.01**
- **함정**: **리깅 후 재익스포트하면 리그 깨짐** → UV·텍스처·리그를 같은 최종 메쉬에서 끝내고 임포트

---

## 🤖 AI 활용 "정상" 파이프라인 (우리 버전)

```
① 컨셉(Seedream 턴어라운드)  ← AI
② 베이스+스컬프트(Meshy/Rodin)  ← AI가 ③④⑤ 압축
③ 리토폴(Remesh/Smart Lowpoly) + 수동 보정  ← AI+사람
④ UV·베이크·텍스처  ← AI 일부 + 사람
⑤ 리깅(오토리그) + 웨이트 보정  ← AI+사람
⑥ UE5 + NPR 셰이더 + LOD  ← 사람
```

> [!tip] 핵심 깨달음
> - AI는 **①②(컨셉·베이스)를 폭압축**. **얼굴·손·눈·토폴로지·리깅 마무리는 여전히 사람**
> - **카툰(셀셰이딩) 목표면 부담 ↓** — 사실적 텍스처/디테일 불필요, 룩은 UE5 토온셰이더가 90%
> - **꼭 지킬 것**: ① 레퍼 먼저 ② 스케일 처음에 ③ 리토폴 엣지루프 ④ 실루엣 유지 ⑤ 리그 후 재익스포트 금지

## 도구 (선택)
- **초보/1인**: **Blender 올인원**(스컬프트·리토폴·UV·리깅·렌더 한 파일)
- **프로**: **ZBrush(스컬프트) + Maya(리토폴/UV) + Substance(텍스처) + Marmoset(룩뎁)**
- 표준은 없음 — 프로젝트 기술 요건 충족이 핵심
