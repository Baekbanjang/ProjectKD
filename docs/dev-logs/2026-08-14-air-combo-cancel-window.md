## 3. 안무 캔슬 프레임 역추출

`.claude/skills/anim-cancel-scan` 절차를 따랐다. 다만 **공중은 지상과 구조가 다르다.**

### 구조 검증에서 갈렸다

지상 팩은 `[Idle] → 공격 → Idle 복귀 → [Idle]`이라 각 타의 `t=0`이 전부 같은 Idle이다. 공중은 아니었다.

```
t=0 포즈끼리 거리        01 vs 02 = 315도 / vs 03 = 658도 / vs 04 = 457도
클립 끝 vs 자기 시작     Air_01 = 2.2도  /  02 = 316  /  03 = 655  /  04 = 450
_All 2.8333s  <  개별 합 4.2500s        ← 잘라 이어붙인 구조는 동일
```

**공중은 Idle 복귀가 없다.** 각 타가 앞 타의 끝 자세에서 그대로 시작한다(`Air_01`만 시작·끝이 같은 자세로 돌아옴). 그래서 "다음 타의 첫 프레임 포즈를 앞 타에서 찾는다"가 그대로 성립한다.

### 두 방법이 차이 0으로 만났다

뼈 11개(`hand_r/l` `foot_r/l` `spine_03` `head` `pelvis` `upperarm_r/l` `thigh_r/l`)의 회전 쿼터니언 각도차 합.

| | A) 다음 타 f0 포즈를 앞 타에서 전역 스캔 | B) `_All` 안의 각 타 시작 위치 |
|---|---|---|
| Air_01 | f25 (거리 **0.0**) | `_All` f0 → f25 = **25프레임** |
| Air_02 | f40 (거리 **0.0**) | f25 → f65 = **40프레임** |
| Air_03 | f55 (거리 **0.0**) | f65 → f120 = **55프레임** |

세 타 모두 **포즈 거리 0.0**(완전 일치)이고 A·B가 **전부 차이 0**이다.

### 적용

| 타 | 이전 | 지금 | dur | 끝 | 사용률 |
|---|---|---|---|---|---|
| Air_01 | **없음** | **f25** (0.4167s) | 0.5000 | f55 = 클립 끝 | 45% |
| Air_02 | f34 (0.5667s) | **f40** (0.6667s) | 0.4167 | f65 = 클립 끝 | 62% |
| Air_03 | f41 (0.6833s) | **f55** (0.9167s) | 0.5000 | f85 = 클립 끝 | 65% |
| Air_04 | f22 | 그대로 | 0.4667 | f50 = 클립 끝 | 마지막 타라 기준 없음 |

`Air_03`이 **14프레임(0.24초)** 빨랐다 — 작성자 육안 관측("좀 빨리 프레임을 찍은듯")과 일치.

`Air_03`의 총격 2발(f23·f41)은 캔슬창 f55보다 앞이라 둘 다 나간 뒤에 끊긴다.
`Air_01`은 총격이 f22, 캔슬창이 f25라 총격 직후 바로 이어진다 — §2의 버퍼 증발 문제도 같이 풀렸다.

## 4. 함정 2개

### `fps = (nf-1)/L` 이 틀렸다

`Air_03`은 85프레임 / 1.41667초다. `(85-1)/1.41667 = 59.29`로 계산해 `55/59.29 = 0.9388s`를 넣었는데, **정답은 `85/1.41667 = 60.0`이라 0.9167s**다. 1.3프레임 늦게 들어갔다.

프레임↔시각 환산은 직접 나누지 말고 **`AnimationLibrary.get_time_at_frame()`** 을 쓴다. 포즈는 프레임 인덱스로 재고 노티는 초로 박으므로 이 환산이 반드시 한 번 끼어든다.

### `GameplayTag`는 파이썬에서 빈 것처럼 보인다

```python
repr(cancel_tag)                          # <Struct 'GameplayTag' {}>      ← 비어 보임
cancel_tag.get_editor_property("tag_name") # State.Combat.CanCancel        ← 실제 값
```

08-12에 `ANS_EnemyAttackWindow`의 태그가 실제로 비어 퍼펙트 회피가 죽어 있던 전례가 있어 같은 결함으로 볼 뻔했다. **`tag_name`까지 꺼내야 판단할 수 있다.** 08-13의 GCN 태그 조회 때도 같은 착시가 있었다.

`UANS_CancelWindow`는 생성자에서 `CancelTag(GameplayTags::State_Combat_CanCancel)`를 넣으므로 노티를 재생성해도 태그가 딸려온다 — 이번 방식(트랙 비우고 새로 추가)이 안전했던 근거.

## 5. 노티 조회·수정 API

`FAnimNotifyEvent`의 `trigger_time`·`duration`은 파이썬 프로퍼티로 안 열린다(protected). 우회로가 따로 있다.

```python
AL.get_anim_notify_event_trigger_time(event)          # 시각 읽기
AL.get_anim_notify_event_duration(event)              # 길이 읽기
AL.get_animation_notify_events_for_track(anim, name)  # 트랙별 조회
AL.remove_animation_notify_events_by_track(anim, name)
AL.add_animation_notify_state_event(anim, track, start, duration, cls)
AL.add_animation_notify_track(anim, name, color)      # 트랙 자체가 없을 때
```

시각을 바꾸는 직접 API는 없다. **트랙을 비우고 다시 추가**하는 방식이다.
