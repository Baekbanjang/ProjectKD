# 닷지 끊김(seam) 해결 = Root Motion Mode 공부 노트 (2026-06-03)

> 승환 공부용 개인 로그 (P4 미공유). 어려운 말 최대한 풀어서 적음.

---

## 0. 먼저 알아야 할 단어 3개

### (1) 시퀀스 vs 몽타주
- **시퀀스(Animation Sequence)** = 그냥 애니메이션 클립 한 개 (걷기, 달리기 한 사이클).
- **몽타주(Animation Montage)** = 시퀀스를 감싸서 "이벤트 끼우고, 도중에 끊고, 슬롯에 얹는" 기능을 붙인 것. 공격·닷지처럼 **딱 한 번 재생하고 끝나는 동작**에 씀.

### (2) 루트모션 (Root Motion)
- 캐릭터 뼈대 맨 위에 **root(뿌리) 뼈**가 있음.
- 보통 걷기 클립은 이 root가 **제자리에 가만히** 있음 (= "in-place" 인플레이스). 발만 움직이지 몸 전체는 그 자리.
- 그런데 어떤 클립은 root 뼈 자체에 **"앞으로 2m 이동" / "180도 회전"** 같은 이동 정보가 박혀 있음. 이걸 **루트모션**이라고 함.
- 닷지/턴 클립이 바로 이 루트모션 방식 — 클립이 직접 몸을 날리고 돌림.

### (3) velocity-driven 로코모션 ("속도가 몸을 움직인다")
- 우리 기본 이동 방식. **코드의 속도 값(MaxWalkSpeed)이 캡슐(몸)을 실제로 움직임.**
- 애니 클립(걷기/달리기 시퀀스)은 **제자리 포즈만** 보여줌 (in-place). 몸이 실제로 가는 건 코드.
- 그래서 C(150)/W(500)/Shift(700) 속도를 코드에서 바꾸면 애니가 알아서 그 속도에 맞는 포즈로 블렌드됨.

**한 줄 요약:** 기본 이동 = **코드가 몸을 움직임 + 클립은 제자리 포즈**. 닷지/턴 = **클립(루트모션)이 직접 몸을 움직임**. 이 둘이 한 캐릭터 안에서 섞임 → 누가 운전대를 잡느냐가 문제.

## 1. 닷지 끊김(seam) 증상

- 달리다 닷지 → 와다다 날아감 → **착지 직전 멈칫(제자리 Idle로 뚝)** → 다시 기본 이동.
- 닷지로 날아간 "기세"가 로코모션으로 안 이어지고 한 번 끊김.

## 2. 처음 시도한 방법들 (다 실패하거나 불필요했음)

### lever 1 — `MoveComp->Velocity = ...` 직접 대입 → **무효**
- 닷지 끝날 때 "현재 속도로 계속 가라"고 Velocity에 직접 값을 박음.
- **왜 안 됨:** CharacterMovement(CMC)가 매 프레임 루트모션을 소비하면서 Velocity를 **다시 덮어씀**. 우리가 박은 값이 같은 틱에 지워짐 → 다음 틱 감속 → 0 → Idle 스냅.

### LaunchCharacter 버전 (`CarryMomentumOnExit`) → **됐을 수도 있었지만 결국 불필요**
- `LaunchCharacter()` = 캐릭터를 **한 번 확 미는** 엔진 함수. 직접 Velocity 대입과 다르게 엔진의 `PendingLaunchVelocity` 경로를 타서 **루트모션 소비가 끝난 뒤에 적용** → 안 덮임.
- 코드상 맞는 해법이었지만, 아래 진짜 원인을 고치니 **필요 없어짐** → 제거(YAGNI).

## 3. 진짜 원인 + 해결 = **Root Motion Mode**

ABP(애님 블루프린트) **클래스 디폴트**에 `Root Motion Mode`라는 설정이 있음. "누가 몸을 움직이는 루트모션을 쓸 거냐"를 정함.

| 모드 | 뜻 | 결과 |
|---|---|---|
| **Root Motion from Everything** (이전 설정) | **모든** 애니(기본 이동 클립까지)의 루트모션을 다 적용 | 기본 이동(velocity 운전)과 닷지 몽타주(루트모션 운전)가 블렌드 구간에서 **운전대를 서로 뺏음** → 속도 충돌 → 멈칫 |
| **Root Motion from Montages Only** (✅ 해결) | **몽타주만** 루트모션으로 몸을 움직임. 기본 이동 클립의 루트모션은 무시 | 기본 이동 = 코드(velocity)가 운전 / 닷지 = 몽타주가 운전 → **권한이 깔끔히 분리** → 안 싸움 → 끊김 사라짐 |

- **이게 Lyra(에픽 표준 샘플) 방식.** velocity-driven 로코모션 쓰면 거의 항상 `Montages Only`.
- 핵심 직관: 기본 이동 클립은 어차피 **제자리(in-place)**라 루트모션이 0 → "Everything"으로 다 켜봤자 기본 이동엔 이득 없고, **닷지 블렌드아웃 구간에서 베이스 포즈가 섞여 들어와 속도만 망침.** 그래서 베이스 그래프 루트모션은 꺼버리는 게 맞음.

## 4. 포즈 ≠ 속도 (헷갈리기 쉬운 부분)

끊김에는 사실 **두 가지**가 섞여 있었음:
| 문제 | 증상 | 담당 해결 |
|---|---|---|
| **속도 끊김** | 날아가다 0으로 뚝 멈춤 | **Root Motion Mode** (위 3번) |
| **포즈 튐** | 다이빙 포즈 → Idle 포즈 한 프레임 점프 | **몽타주 Blend Out 0.2~0.3s + `ANS_MovementCancel`** |
- Blend Out(블렌드아웃)은 **포즈만** 부드럽게 섞어줌 — 실제 멈춤(속도)은 못 고침. 그래서 둘 다 필요한 것처럼 보였는데, 속도는 Root Motion Mode가 통째로 해결.

## 5. 부작용 → 다음 작업: 180도 턴

- `Montages Only`로 바꾸니 **기존 180도 턴이 깨짐** (아예 안 돎).
- **왜:** 예전 180턴은 회전 루트모션이 박힌 클립을 **로코모션 스테이트머신 안의 state**로 넣고 `Everything`을 요구했음. `Montages Only`로 바뀌자 **스테이트머신 안 클립의 루트모션은 무시** → 캡슐을 못 돌림.
- **해결 방향:** 180턴을 **몽타주 + GA(GameplayAbility)** 방식으로 재설계. 몽타주는 `Montages Only`에서 정상 작동(닷지로 검증됨). 단 프리 모드는 orient-to-movement(입력 방향으로 자동 회전)가 항상 켜져 있어 턴 루트모션과 싸움 → **GA가 켜질 때 끄고, 끝날 때 다시 켜기** (닷지 GA가 무적 GE 켜고 끄는 패턴과 똑같이).

## 한 문장 결론
> **velocity-driven 로코모션 + 루트모션 동작(닷지/턴/공격)을 한 캐릭터에 섞을 땐, ABP `Root Motion Mode = Root Motion from Montages Only`로 "기본 이동은 코드, 특수 동작은 몽타주"로 운전 권한을 분리한다. (Lyra 표준)**
