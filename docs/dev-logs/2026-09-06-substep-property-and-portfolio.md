## 1. 서브스텝 상한을 GA 프로퍼티로

### 왜

포폴에 **"보간 없으면 이렇게 된다"** 를 찍어야 하는데, 상한이 `.cpp` 익명 네임스페이스 상수라 **바꿀 때마다 재컴파일**이었다.

우회를 찾았으나 없었다.

```
TraceMode = TipLine     서브스텝은 없어지지만 그림이 얇은 선 1개로 바뀐다 — 대조가 안 산다
ArcBulge = 0            직선이 될 뿐 서브스텝은 그대로 돈다
TraceSegments = 1       칼 축 분할만 줄인다. 진행 방향은 그대로
```

### 무엇을

```cpp
// 삭제
constexpr int32 MaxSubStepsSweep = 8;
constexpr int32 MaxSubStepsArc   = 32;

// 신설 — KDGameplayAbility_MeleeTrace.h:74
UPROPERTY(EditDefaultsOnly, Category = "Action|Weapon", meta = (ClampMin = "1", ClampMax = "64"))
int32 MaxSubSteps = 8;
```

`ArcBulge`·`TraceSegments` 와 같은 패턴. 팩토리 인자 → 멤버 → `Clamp(..., 1, MaxSubSteps)` 두 곳(`:169` Sweep · `:227` Arc)으로 통일.

### 🔴 통합 부작용

**Arc 계열 기본값이 32 → 8 로 내려갔다.** `GA_LightCombo`·`GA_HeavyCombo` 만 CDO 에서 32 로 올렸으니, **새 Arc 모드 GA 를 만들면 8 로 시작한다.**

```
목표 간격 5cm x MaxSubSteps = 커버 가능 이동거리
  8  = 40cm   10fps 큰 횡베기(틱당 300cm)면 37.5cm 간격으로 벌어진다
  32 = 160cm
```

⚠️ **`GA_HeavyCombo` 가 실제로 32 인지 확인 못 했다** — Content 커밋 `3bdbd7e` 메시지가 `GA_LightCombo` 만 언급한다(볼트 지적). 에디터 꺼져서 `inspect_cdo` 불가. **다음 세션 최우선 확인.**

### 📌 상한 8 의 정체

git 로그를 뒤졌으나 **최초 도입 커밋을 못 찾았다.** 파일 개명(`AT_WeaponTrace` → `KDAbilityTask_MeleeTrace`) 이전부터 있었고 **주석도 dev-log 근거도 없다.** velog 원본(우리가 참고한 구조)에는 상한이 아예 없다 — 우리가 임의로 넣은 값이다.

🟡 추정 = 트레이스 횟수 제한(성능). 확인 불가.

★ **그 8 이 저프레임 결함의 일부였다.** `StepDist 5cm` 의 의도는 "5cm마다 검사"인데, 상한 8은 **이동 40cm 이하에서만** 그 의도가 지켜진다.
